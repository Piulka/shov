# Запущенная Telegram-бета

Состояние на 9 сентября 2026 года. Это протокол первого запуска; дальнейшие обновления могут изменить версии и конфигурацию. Общие команды эксплуатации находятся в [инструкции развёртывания](13-beta-deployment.md).

## Адреса и версия

- Mini App: <https://shovrpg.ru>.
- Бот: <https://t.me/shovRPG_bot>. Открыть личный чат, отправить `/start`, нажать «Играть». Также настроена кнопка меню «Играть».
- Вход открыт любому пользователю Telegram: `BETA_ACCESS=open`. Открытие адреса обычным браузером без Telegram не авторизует игрока.
- Рабочий код: `262de1813f79ec884a6438a1c3ed95fa27863d89`, версия приложения `0.5.0`.
- Образы: `shov:262de1813f79`, `shov-caddy:262de1813f79`. Комплект графики и звука из `4007ae4` включён полностью.
- Репозиторий на VPS: `/opt/shov`; секретная конфигурация: `/opt/shov/.env`, права `0600`. Секреты не входят в git и Docker-образы.

## Выполнено

Домен разрешается в адрес VPS, Caddy выпустил доверенный HTTPS-сертификат и перенаправляет HTTP на HTTPS. Первоначальная задержка была связана с публикацией делегации недавно зарегистрированного домена. Запись A у DNS-хостинга уже была правильной.

Приложение и Caddy работают отдельными контейнерами от UID 1000, с файловой системой только для чтения, постоянными volumes, ограниченными логами и автоматическим запуском Docker. Наружу доступны SSH и HTTP/HTTPS; порт приложения 3001 не опубликован. UFW включён. Парольный SSH-вход отключён; доступ по существующему ключу сохранён.

Установлены доступные обновления Ubuntu 24.04, включая OpenSSH, OpenSSL и ядро `6.8.0-139-generic`. После перезагрузки проверены новый SSH-вход по ключу, автоматический запуск контейнеров и таймера резервного копирования; неуспешных системных служб нет.

Telegram подтвердил токен, кнопку меню и webhook `https://shovrpg.ru/api/telegram/webhook`. При настройке очередь была пустой, ошибок доставки не было. Проверены отказ запросу без секрета и принятие подписанного служебного запроса без сообщения. Это не заменяет настоящий `/start` с телефона.

Таймер `shov-backup.timer` делает согласованный снимок SQLite каждые шесть часов, в 00/06/12/18 UTC с задержкой до пяти минут. Первый снимок восстановлен в отдельный файл на VPS, затем скачан на компьютер владельца и независимо восстановлен там. Рабочая база не подменялась. Начальная база не содержит тестовых игровых аккаунтов, созданных проверкой развёртывания.

## Проверки

- 163 модульных и интеграционных теста, сборка TypeScript/Vite, проверка проектной документации.
- [GitHub Actions рабочего коммита](https://github.com/Piulka/shov/actions/runs/34335342084): успешные тесты, Docker-сборка, запуск контейнера, резервное копирование и восстановление.
- Проверка `tools/check-deploy.mjs` по настоящему HTTPS: API, Telegram-режим, база, интерфейс и отказ анонимному запросу состояния.
- 43 PNG проверены по размерам, хешам, цветовым параметрам и прозрачности. Все 104 звуковых файла в OGG/M4A декодируются в браузере.
- Все 147 опубликованных медиафайлов побайтно совпадают с файлами репозитория. Проверены MIME, кэширование, аудиоманифест и 404 для отсутствующих ресурсов.
- Браузерные проверки: включение звука жестом, воспроизведение, mute, сохранение громкости и скрытие/возврат. Сцена, карта и экипировка проверены на ширинах 320/390/768/1440; три региона отдельно проверены на 390/1440.
- Локальный замер сцены: примерно 28 кадров/с при ограничении Canvas около 30. Это не замер Telegram на физическом телефоне.
- Публичный экран входа проверен на 390/1440 без ошибок JavaScript и горизонтального переполнения.

## Что осталось

1. На реальных Telegram Android, iOS и Desktop проверить `/start`, первый вход, повторное открытие, сохранение прогресса, сворачивание и звук. Подлинный вход пользователя во время автоматического развёртывания не выполнялся.
2. В BotFather при необходимости включить Main Mini App с URL `https://shovrpg.ru/`. На момент проверки `has_main_web_app=false`: настроенные меню и кнопка `/start` уже открывают игру, а запуск из профиля и ссылка `?startapp` отдельно не подтверждены.
3. Подключить постоянное внешнее хранилище резервных копий и мониторинг недоступности, неуспешных копий и заполнения диска. Сейчас снимки автоматически остаются на VPS; на компьютере владельца есть только начальная внешняя копия. Автоматическое удаление старых копий не включено.
4. Провести нагрузочный тест перед массовым приглашением. Текущее развёртывание рассчитано на один процесс API и одну SQLite, без высокой доступности и обновления без простоя.
5. Графика и звук подключены, но покадровые атласы анимации и музыка не входят в переданный комплект. Используются PNG с существующей Canvas-анимацией. Дополнительные заготовленные SFX пока не все привязаны к событиям; детали в [описании комплекта](../assets/art-audio-v1/README.md).

Перед расширением аудитории эти пункты нужно закрыть по результатам реального бета-теста. Локальные скриншоты, отчёт сверки и начальная резервная копия находятся в игнорируемом git каталоге `.local/deployment/` компьютера владельца.
