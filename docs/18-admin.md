# Административная панель

Панель доступна на отдельном адресе <https://admin.shovrpg.ru>. Она использует отдельный пароль и сессию, не связанную с Telegram-аккаунтами. Вход не требует логина пользователя. Пароль первого развёртывания сохранён только на компьютере владельца в `.local/deployment/admin-access.json`; он не входит в git или образ приложения.

## Возможности

- Сводка: число игроков и кланов, обновления сохранений за 24 часа и семь дней, распределение уровней, маршрутов и монет, суммарные ресурсы, победы и поражения.
- Поиск по ID, имени героя и публичному имени, постраничный список игроков.
- Карточка игрока: текущие характеристики, уровень, опыт, кошелёк, усиления, маршрут, цель добычи, инвентарь, активная сборка и сохранённые наборы.
- Выдача, изменение, надевание и удаление предметов, редактирование умений и условий боя, блокировка и разблокировка аккаунта.
- Подтверждение изменений с обязательной причиной и записью в журнал. В SQLite сохраняются исходное состояние, результат расчёта прошедшего времени, итоговое состояние и побочные эффекты правки.

Характеристики рассчитываются из уровня, вещей и усилений. Произвольные коэффициенты здоровья и силы, RNG, ID аккаунта и сырой JSON сохранения не редактируются. Валидация проверяет слоты, редкости, свойства, навыки и ссылки сохранённых сборок. Используемый предмет сначала нужно заменить во всех сборках, прежде чем удалять. Закрепление вещи снимается явно.

Имя героя в кампании и публичное имя в сообществе пока хранятся отдельно. В списке показывается публичное имя, если оно создано; искать можно по обоим. Старые записи ленты клана сохраняют имя на момент сообщения.

## Сохранение и конфликты

Просмотр рассчитывает доступный офлайн-прогресс в памяти, не сохраняет героя и не продлевает автономность. Агрегаты сводки основаны на сохранённых данных. «Обновления за 24 часа» означает число аккаунтов с обновлённым сохранением, включая изменения администратора; это не DAU, число входов или удержание. История посещений и когортные метрики пока не собираются.

Перед подтверждением панель получает актуальную версию игрока. Если сохранение успело измениться, сервер возвращает конфликт. Черновик остаётся: нужно загрузить актуальные данные, проверить новые значения и подтвердить снова. Активная игра обновляется часто; кнопка «Обновить расчёт» позволяет освежить данные после ввода причины. Изменения автоматически не повторяются с новой версией. Повторная отправка того же успешно выполненного запроса не выдаёт предметы второй раз.

Перед изменением сервер рассчитывает уже прошедшее время по старой сборке. Правки ресурсов, имени, цели добычи и блокировки сохраняют текущий бой. Изменения боевых характеристик начинают новый бой с момента правки; незавершённый бой не приносит награду. Некорректные запланированные сборки и маршруты отменяются, что отмечается в журнале. Правки администратора не дают дополнительные 48 часов автономности.

## Устройство и развёртывание

Один процесс Node.js обслуживает два отдельных Fastify listener: игровой API на 3001 и администрацию на 3002. Оба работают с одной локальной SQLite, а изменения выполняются синхронными транзакциями. Порт 3002 не публикуется Docker наружу. Caddy направляет запросы отдельного административного домена только на этот listener. Игровой API не регистрирует административные маршруты.

Для первого включения создать отдельную A-запись административного поддомена на VPS и сгенерировать доступ:

```sh
node tools/admin-credentials.mjs https://admin.example.com .local/admin-access.json
```

Команда создаёт новый файл с паролем и scrypt-хешем, отказывается перезаписывать существующий и не печатает пароль. Файл следует хранить с ограниченными правами, вне репозитория. На Windows дополнительно ограничить ACL каталога; Unix-права `0600` сами по себе не настраивают Windows ACL.

В защищённой серверной `.env` задать `ADMIN_ORIGIN=https://admin.example.com` и `ADMIN_PASSWORD_HASH` из файла. Значение хеша должно быть в **одинарных кавычках**, чтобы Docker Compose не интерпретировал разделители `$` как подстановки переменных. Открытый пароль серверу не передаётся. Адрес админки обязан отличаться от `APP_ORIGIN`.

Для включённой админки всегда использовать оба Compose-файла:

```sh
cd /opt/shov
docker compose --env-file .env -f deploy/compose.yaml -f deploy/compose.admin.yaml config --quiet
docker compose --env-file .env -f deploy/compose.yaml -f deploy/compose.admin.yaml build
docker compose --env-file .env -f deploy/compose.yaml -f deploy/compose.admin.yaml up -d --wait
docker compose --env-file .env -f deploy/compose.yaml -f deploy/compose.admin.yaml ps
```

Запуск `up` только с базовым файлом отключит административный listener и его HTTPS host. Резервные копии используют прежний общий volume и включают журнал администрации. Правила обновления образов, резервных копий и отката описаны в [инструкции сервера](13-beta-deployment.md).

## Доступ

Пароли проверяются scrypt, попытки входа ограничены. Сессия действует восемь часов, хранится как хеш случайного токена и передаётся в отдельной cookie `__Host-shov_admin` с `Secure`, `HttpOnly`, `SameSite=Strict`, без атрибута Domain. Все POST требуют точного Origin административного сайта. Чужие игровые cookie не дают доступа; запросы без сессии не раскрывают данные игроков. Страница запрещает встраивание во фрейм.

Чтобы сменить пароль, сгенерировать новый файл доступа, заменить только хеш в защищённой `.env` и пересоздать контейнер с обоими Compose-файлами. Смена хеша аннулирует старые административные сессии. После восстановления сервера из старой копии рекомендуется сменить пароль, чтобы не восстанавливать действительность старых сессий.

Пока предусмотрен один административный доступ владельца. Отдельные роли сотрудников, двухфакторная авторизация, автоматические предупреждения об аномалиях и историческая аналитика удержания в эту версию не входят.

## Проверенный выпуск

9 сентября 2026 года панель включена на <https://admin.shovrpg.ru>. Игра и панель работают из коммита `cd001cd627e7ca5acd4e98a61345b99d1b55edbb`, образы `shov:cd001cd627e7` и `shov-caddy:cd001cd627e7`.

- 177 модульных и интеграционных тестов, сборка TypeScript/Vite, проверка документации и [GitHub Actions](https://github.com/Piulka/shov/actions/runs/34345883511) прошли успешно.
- Браузерные сценарии на отдельной базе проверили сохранение незатронутого прогресса, конфликт версий, выдачу и надевание вещи, изменение тактики, журнал и выход. Экраны и диалоги проверены на ширинах 320, 390 и 1440 пикселей.
- На опубликованном сайте проверены HTTPS, вход, защищённая cookie, чтение списка и карточек игроков, отказ без сессии, запрет запросов с чужого сайта и недоступность административного API на игровом домене. Проверки не редактировали настоящих игроков.
- Перед обновлением и после него созданы резервные копии SQLite. Последняя проверена отдельно: целостность в порядке, все восемь существовавших на момент выпуска игроков и таблицы администрации присутствуют. Копия также скачана на компьютер владельца в `.local/deployment/admin-release-backup.sqlite`. Плановые копии на VPS каждые шесть часов продолжают работать.
- Оба контейнера здоровы; порты приложения 3001 и 3002 наружу не опубликованы. Игровой HTTPS и подписанный запрос webhook без сообщения проверены; очередь Telegram пуста. Запись Telegram об отказе соединения от 10:38:34 UTC предшествует этому обновлению и не означает текущий сбой.

Автоматического внешнего хранилища резервных копий пока нет: скачанная копия разовая. Ограничения первой беты перечислены в [протоколе запуска](16-live-beta.md).
